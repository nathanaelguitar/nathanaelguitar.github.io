I fine-tuned a 27B model on IBES. Most of the score was formatting.

Nathanael Gill · Cornell MSBA · November 2026

The short version

I QLoRA fine-tuned Qwen3.6-27B on analyst estimate-revision events from WRDS/IBES and evaluated it on a 1,000-event holdout. Accuracy went from 0.449 to 1.000.

The score is real. But most of the improvement is formatting, not financial reasoning.

The base model was already getting the direction right when it returned a valid answer. The adapter mostly learned to follow the JSON schema and handle neutral correctly. I wanted to measure how much of the improvement was actually meaningful.

Setup

Each event is an analyst revision record. The model reads the event and returns JSON with a direction (positive, neutral, negative) and a magnitude bucket.

I used a PySpark bronze-silver-gold pipeline to build the events from raw WRDS pulls. Labels come from the change in consensus. Below a threshold, the label is neutral. Otherwise, it takes the sign.

Random split with a fixed seed. Training ran in 4-bit on one NVIDIA DGX Spark.

I evaluated the base and adapter on the same holdout, same prompt, nonthinking mode, temperature zero.

1.000 accuracy looks great. But a perfect score on a financial task deserves some scrutiny.

What the base model was actually doing

The base model returned parseable answers on 466 of 1,000 events.

Here’s the interesting part. When it actually returned a direction, it was correct every time. 447 of 447 positive and negative calls.

Neutral was the problem. 332 of 351 neutral events were unparseable. Of the other 19, 17 were classified as negative.

So the adapter didn’t suddenly learn to understand analyst revisions. It mostly learned to return valid JSON consistently and recognize neutral as an actual answer.

And the task itself matters here. The label is determined by applying a threshold to a number already in the input. Once the formatting issue is fixed, perfect accuracy isn’t particularly surprising.

This is close to a deterministic classification task. It’s not evidence that I built a financial forecaster.

More data bought almost nothing on the holdout

I compared a 1k-event run against a 10k-event run.

Both scored 1.000 accuracy on the holdout. Exact JSON match improved from 0.994 to 0.999.

Ten times the training data for half a point. Not much.

And the larger run actually did a little worse on most of the four public sentiment benchmarks (64 examples each).

The FPB drop came from 11 neutral sentences flipping to positive.

I also checked for IBES-style JSON leaking into the public benchmarks. Found no sign of it.

These are small samples, though. At 64 examples, a benchmark can move by five or six answers. I wouldn’t treat this as proof. It’s a signal worth investigating.

Also worth clarifying: this table compares the two adapters, not the base model.

What I would do next

I’d split by company and time instead of relying on a random split. I don’t want the model leaning on firms it has already seen.

I’d also make neutral more challenging than a simple threshold, evaluate magnitude separately, and run the base model on the same public benchmark slices.

That would give me a more complete comparison of what the fine-tuning actually improved.

Data

WRDS/IBES is licensed data. The repository includes code and aggregate metrics only. No raw records, predictions, adapters, or checkpoints.
