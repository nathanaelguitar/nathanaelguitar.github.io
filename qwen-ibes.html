I fine-tuned a 27B model on IBES. Most of the score was formatting.

Nathanael Gill · Cornell MSBA · November 2026

The short version

I QLoRA fine-tuned Qwen3.6-27B on analyst estimate-revision events from WRDS/IBES. Tested it on a 1,000-event holdout. Accuracy went from 0.449 to 1.000.

Sounds impressive. But most of that jump was formatting. When the base model did answer, it got the direction right. It just wasn’t answering in the JSON format I asked for. I wanted to separate actual improvement from schema compliance.

Setup

Each event is an analyst revision record. The model reads it and returns JSON with a direction (positive, neutral, negative) and a magnitude bucket.

I built the dataset using a PySpark bronze-silver-gold pipeline from raw WRDS pulls. Labels come from the change in consensus. Below a threshold is neutral. Otherwise, the sign determines the direction.

Random split, fixed seed. Training ran in 4-bit on one NVIDIA DGX Spark. I tested the base and adapter on the same holdout, same prompt, nonthinking mode, temperature zero.

A perfect score on a financial task is suspicious. So I looked at what was actually happening.

What the base model was actually doing

The base model returned parseable answers on 466 of 1,000 events. When it gave a direction, it was right every time: 447 of 447 positive and negative calls.

Neutral was the problem. 332 of 351 neutral events came back unparseable. Of the other 19, 17 were called negative.

So what did the adapter actually learn? Mostly to follow instructions. It learned to always return valid JSON and to treat neutral as a valid answer.

The label is just a threshold applied to a number already in the input. Once the formatting is fixed, a perfect score makes sense. This doesn’t mean I trained a financial forecaster. It means the task is close to deterministic.

More data bought almost nothing on the holdout

I trained on 1k and 10k events. Both runs hit 1.000 accuracy on the holdout. Exact JSON match went from 0.994 to 0.999. Ten times the data for half a point.

And there was a tradeoff. On four public sentiment benchmarks (64 examples each), the bigger run was mostly a little worse.

The FPB drop came from 11 neutral sentences flipping to positive. I found no sign of IBES-style JSON leaking into the public benchmarks.

Also, these are small samples. At 64 examples, a benchmark can move by five or six answers. So I wouldn’t call this proof of anything. It’s a direction worth investigating.

And to be clear, this table compares the two adapters, not the base model.

What I would do next

I’d split by company and time. I don’t want the model leaning on firms it has already seen. I’d also make neutral harder than a simple threshold, evaluate magnitude separately, and run the base model on those same public benchmarks.

Data

WRDS/IBES is licensed data. The repository contains code and aggregate metrics only. No raw records, predictions, adapters, or checkpoints.

Numbers come from the aggregate metrics files in the project repository: the 10k holdout run, the 1k-on-10k run, and the public benchmark runs.
